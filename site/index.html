Everything starts in VS Code

Set up your agents
from VS Code.

Open the Command Palette with ⇧⌘P on macOS or Ctrl+Shift+P on Windows and Linux. Type Agent Gateway to find status, setup, sharing, and search.

  1. 01
    Install and allow Copilot access

    Install Agent Gateway from the Marketplace. When VS Code asks to let it use Copilot’s language models, choose Allow.

  2. 02
    Check that the gateway is ready

    Click Gateway in the status bar or run Agent Gateway: Status. Confirm that it says Ready.

  3. 03
    Choose your agents and model

    Run Configure Coding Agents, review changes, and confirm. Follow the remaining setup or restart instructions for each agent.

Configuration changes are reviewed before saving, backed up, and reversible through Remove gateway.

01 — A closer look

Your Copilot models.
More ways to use them.

Keep the agent’s file edits, shell commands, and MCP tools. The gateway handles the model connection, API translation, and the settings in between.

/ 01   Local or another machine

Share Copilot models
across machines.

Work through the local gateway, or bring models from another machine into the same list. On the host, use Share Gateway via Dev Tunnel. On the other machine, add its URL and key in Manage Remote Upstreams.

Tunnel hosting runs in an extension-managed background process, not an integrated terminal. Use Stop sharing to end it; extension shutdown also stops hosting.

Set a gateway API key before sharing. Anyone with the tunnel URL and key can use the host’s models. Initial devtunnel installation or sign-in may still need an interactive terminal.

/ 02   Search & read the web

Add web search
and page fetching.

Enable supported web search and URL fetch tools through Web Search and Fetch. Pick an engine, add a key if required, and let compatible agents bring web sources into their work.

Choose from Exa, Firecrawl, Tavily, Jina AI, or You.com. Exa and Firecrawl offer rate-limited anonymous search and fetch. Jina AI offers anonymous fetch; Tavily and You.com require keys.

Off by default. Provider limits apply, and tool support varies by API and agent. Search-service keys stay in VS Code secret storage; queries and page text are not logged.

/ 03   Deliberate model routing

Choose your model mappings
and fallback.

Choose your main model in agent setup. If a background task requests a different name, use Set Fallback Model to map that specific name to a compatible local model.

An optional fallback handles unknown model names only for supported APIs. Select a compatible local or remote model explicitly. The default is No fallback; the gateway does not pick one for you.

Fallback is not failover: an error from an existing model does not trigger it. Gemini unknown names use mappings or aliases, not the general fallback rule. AI-assisted mapping suggestions can be reviewed before saving and use Copilot quota.

/ 04   See the connection clearly

Copy API URLs.
Inspect request logs.

Open Status to inspect models, remotes, and recent errors. Under API URLs, copy endpoints using your configured port—including Anthropic and Gemini token-count URLs.

Use request IDs to follow failures in the output panel or error log. Remote metadata is labeled with the upstream name, so you can see where a request went without logging the conversation.

Prompts, request bodies, tool arguments, search queries, URLs, page text, and keys are not logged. The sample here uses placeholder metadata—not a real request.

03 — Before you begin

Frequently asked
questions.

Is this another model subscription?

No. Agent Gateway is an MIT open-source VS Code extension, not a model provider. It connects tools to models your signed-in Copilot account can access. Your provider’s quotas and account requirements still apply.

Does VS Code need to stay open?

Yes. The gateway runs inside VS Code. Closing it stops the local service; shutting down the extension also stops its tunnel hosting. There is no separate gateway server to deploy.

Does my code stay on my computer?

The gateway listens on loopback by default, but model requests still go to the provider that serves the selected model. Remote gateways and optional web tools introduce the services you choose. Prompts and keys are not logged; agent settings and backups may contain a gateway key and should be treated as sensitive.

Will every agent feature work?

No. Your agent’s own edits, shell commands, and MCP tools stay with the agent. Provider-hosted features vary: supported search and fetch tools can run through the gateway, but hosted code execution and some other server tools are not supported. Check tool support ↗

Can I undo the setup?

Yes. Use Configure Coding Agents → Remove gateway to revert the gateway’s entries. Changed files have backups. You can also disable the gateway without uninstalling it by setting agentGateway.enabled to false.
